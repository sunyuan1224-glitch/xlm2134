# MyNovel

MyNovel 是一款**本地优先**的轻量小说写作桌面应用。当前版本为 **v0.1 原型**，优先面向 Arch Linux，
技术栈为 Tauri 2 + React 19 + TypeScript + Rust + CodeMirror 6。

正文以普通 Markdown 文件保存，作品资料以人类可读的 JSON 存在同一个目录里：
不依赖云端账户、不需要数据库，也不联网。应用内的「帮助 → 关于 MyNovel」里有一份面向作者的
「能做什么 / 用着放心的地方 / 已知限制」清单，本文件偏开发者视角。

## 打开软件

在 Arch Linux 上，使用已经打好的 AppImage，不需要启动开发服务器，也不需要先安装 npm 依赖：

```bash
cd /home/error02/Projects/MyNovel
./src-tauri/target/release/bundle/appimage/MyNovel_0.1.0_amd64.AppImage
```

该文件目前已有可执行权限。如果从别处复制后提示权限不足，可以先运行：

```bash
chmod +x /home/error02/Projects/MyNovel/src-tauri/target/release/bundle/appimage/MyNovel_0.1.0_amd64.AppImage
```

打开窗口后，点击 **选择工作区目录**，选择一个用于存放小说的文件夹。可以选择空文件夹，然后在应用中创建章节；
也可以选择已有 Markdown 文件的目录。后续通过顶部的工作区名称切换目录。

> **提示：** 推荐先在工作区根目录右键「新建书」，再在书里建卷和章——**纲要跟着书文件夹走**，
> 只有属于某本书的章才有 总纲 / 卷纲 / 章节纲要。章也可以直接放在工作区根目录（不设卷、也不建书），
> 或先「新建卷」再建章，这些布局都能正常写作与导出，但散在根目录（或根级卷里）的章没有纲要。
> 伏笔 / 时间线 / 设定等资料落在作品目录同层的 `.novel/` 里。

**注意：** `npm run dev` 启动的浏览器预览无法访问 Tauri 原生文件系统，不能在浏览器页面里选择工作区。
需要调试桌面版时，在项目根目录运行 `npm run app`；日常使用直接运行上面的 AppImage 即可。

## 界面一览

界面按 Typora 的版式组织，配色是一套暖白柔粉的亮色主题（CSS 变量集中在 `src/styles.css` 的 `:root`）。

- **顶部菜单栏**：文件 / 编辑 / 段落 / 格式 / 视图 / 主题 / 帮助，快捷键提示右对齐。悬停切换菜单，
  点击外部或 `Esc` 关闭。
- **左侧栏**（默认展开，宽 272、可拖拽 200–560）：「文件 / 大纲」两个文字标签，最右侧是正方形放大镜按钮
  打开工作区搜索。「大纲」标签是整个工作区的纲要导航树（书 → 卷 → 章），点一行就在正文区打开它；
  `Ctrl+Shift+L` 开关；点标签只切换、不折叠，连点或双击当前标签都不会收起侧栏
  （收起只剩「视图 → 左侧栏」与 `Ctrl+Shift+L` 两个显式入口）。
- **正文区**：居中约 752px 栏宽，与 Typora 的 `#write` 一致；上方是多标签页，标签栏会在有未保存改动时
  显示「保存」按钮。
- **右侧「小说工作台」**（默认收起，宽 340、可拖拽 240–640）：伏笔 / 时间线 / 设定 / 校对四个面板，
  导航按「创作 / 校对」两组收进下拉菜单，展开状态与上次的面板会记住，
  可用菜单「视图 → 小说工作台」、右缘竖条把手或 `Ctrl+Shift+B` 召回。
- **底部状态栏**：左侧是工作区名与当前文件相对路径；右侧是 `行 X 列 Y`、选区长度、本章字数（点击循环切换
  统计口径）、全书字数，以及 `● N 未保存` 或最近一条状态文本。

## 功能清单

### 编辑与即时预览

- **即时预览（Live Preview）**：光标所在的块显示 Markdown 源码，其余块渲染成排版后的样子。
  渲染与导出走同一份 `mdExport`，做到「预览所见即导出所得」；复杂到无法可靠渲染的容器块不硬渲染，
  只标记提示并保留完整源码。
- **支持语法**（小说写作够用的一组）：粗体、斜体、下划线、删除线、行内代码、行内 / 引用式 / 自动链接、
  图片、引用块、无序与有序列表、分割线、围栏代码块、缩进代码块、YAML frontmatter（折叠卡片）、行内 HTML；
  标题（ATX / Setext）仍照常渲染——`总纲.md` 就靠 `# 书名` / `## 第N章` 分层，只是正文不再提供插入标题的命令。
- **刻意不做**：公式、图表（Mermaid）、表格、脚注渲染、提示块、`[TOC]`、代码语法高亮、任务框。
  这些语法写进正文不会报错，但按普通文本显示（旧稿因此不会错乱）；解释见「关于 MyNovel → 已知限制」。
- **预览是只读的**：点击渲染块只把光标移到该块起点，绝不把渲染结果写回正文。
- **输入法（IME）**：组合期间会推迟源码模式重配、打字机滚动与外部正文同步，直到组合结束再结算；
  外部内容与本地输入冲突时保留本地文字，只合并互不重叠的改动。

### 视图与排版

- **三种视图模式**：源码模式 `Ctrl+/`（显示原始 Markdown）、专注模式 `F8`（提亮当前行、其余变淡）、
  打字机模式 `F9`（光标行保持垂直居中）。切换源码模式不改动、也不丢失正文。
- **沉浸写作**：独立的全屏写作视图，顶栏有 `A−` / `A+` / `A0` 直接调整字号，双击正文可切换。
- **浮动格式工具栏**：选中文字后在选区上方浮出加粗 / 斜体 / 删除线 / 超链接 / 插入图片，
  可在「视图 → 浮动工具栏」关闭。
- **字体与排版**（`Ctrl+,`）：编辑器字体族（宋体 / 黑体 / 中圆体 / 等宽预设，或自定义字体名）、
  字号 12–34px、行距 1.3–2.8。设置写在 `localStorage` 的 `mynovel:typography`，
  常规编辑器与沉浸写作共用同一套变量。
- **窗口级字号**：`Ctrl+Shift+=` / `Ctrl+Shift+-` 整体放大缩小，`F11` 全屏。

### 查找、导航与组织

- **快速打开文件** `Ctrl+P`（子序列模糊匹配，↑↓ 选择、Enter 打开）。
- **文档内查找 / 替换** `Ctrl+F` / `Ctrl+H`。
- **工作区搜索** `Ctrl+Shift+F`：跨文件全文搜索，支持正则与区分大小写。
- **大纲页（纲要导航树）**：纲要全都跟着书文件夹走，是 `书/outline/` 下的普通 `.md`，**不进文件树**。
  左侧「大纲」标签把它们按 书 → 卷 → 章 排成一棵树：书行就是这本书的总纲（玫红，固定 `总纲.md`），
  卷行是卷纲（青蓝），章行是该章的章节纲要（缩进在所属卷下）。顺序取自文件树的同一份排序，
  所以卷号、手动章序两边永远一致。这个页面只负责「找」：**点任意一行就把它在正文区打开**
  （和章节一样是一个标签页，同一台编辑器、同一套即时预览与 IME 处理，`Ctrl+S` 保存）。
  还没有的章节纲要显示成虚线「＋」，点一下按章名建出来；双击除总纲外的行可以改名。
  每本书的书行还可以折叠。
- **文件树**：新建 / 重命名 / 删除 / 拖拽排序、右键菜单、新建卷、行内改名；
  删除前弹确认框，文件夹删除会显示将一并删除的文件数与未保存修改数。
  拖章时可以落到章行上（插到它前/后）、落到目录行上（整体移入），也可以落到**卷行的上/下边缘**上
  （插到这一卷的前/后 —— 松散章夹进两卷之间走这里，见「排序」一节）。
  右键**书文件夹**还可以「反转卷与章的顺序」：把这本书的卷与章在左侧倒过来列（再点一下
  「还原卷与章的顺序」恢复）。这是**纯显示**的开关——顺序侧车、阅读顺序、EPUB 导出都不受影响，
  所以反着显示时拖拽的方向会自动换算（「插到某章前面」在侧车里记成「后面」）。
- **删除会带上对应纲要**：纲要挂在书目录的 `outline/` 下、不在被删条目的子树里，所以删章会
  一并删掉它的章节纲要，删卷会带上卷纲和卷里各章的纲要（子目录里的章同理），免得留下对不上
  任何章的孤儿。删除确认框会把要一起走掉的纲要列出来。

### 卷与章节

- **卷 = 目录**：目录名匹配「第X卷 / 卷X / Volume N」即识别为卷，也可由卷注册表登记（面板里「新建卷」
  创建的目录走注册表）。整本书可以不设卷，章直接放在书目录下，此时所有章都是「松散章」，
  EPUB 目录保持扁平。
- **纲要文件**：一律放在**书文件夹**的 `outline/` 下，都是可改名、可编辑的普通 `.md`：
  - `书/outline/总纲.md` —— 书级总纲（名字固定），新建书 / 在根目录新建文件夹时自动建；
  - `书/outline/<卷目录名>.md` —— 卷纲，新建卷时自动建，卷改名时跟着改名；
  - `书/outline/<章文件名>.md` —— 章节纲要，右键章节「新建章节纲要」按需建（建章**不会**自动生成）。

  书改名时整份 `outline/` 随目录一起搬。有章却没有总纲时会自动补建。纲要不计入字数、不进
  EPUB 的章节列表。只有属于某个书文件夹的章才有纲要：散在工作区根目录（或根级卷里）的章
  没有纲要，「新建章节纲要」对它们不可用 —— 先给它们建一本书。
- **新建章节**：菜单「文件 → 新建章节」或文件树右键「添加章节」，落到指定目录，正文是**空白**的——
  章节名由文件名管理，正文里不再生成 `# 标题`（否则改名后两处标题会打架）。
- **默认章名接着上一章排**：目录里阅读顺序最后的那一章叫「第三章」，新建的默认名就是「第四章」；
  中文数字、阿拉伯数字、罗马数字各排各的（`第一章`→`第二章`、`第3章`→`第4章`、`第IX章`→`第X章`），
  「第一章 启程」这样带标题的也算，只是新名字只给章号、标题要自己写。只看前一章叫什么，不看编号是否连着——
  目录里是「第一章、第四章」时，新建得到的是「第五章」，顺序乱了得自己改。
  前一章不是「第X章」这个格式（比如「楔子」），或在空目录里新建，就还是 `Untitled`。
  两者都会自动避开重名（`Untitled`、`Untitled 2`…），建好就在树里进入行内改名。
- **拆章**：在编辑器里右键 →「在此拆分章节」，从光标处把当前章拆成 `{名}-上.md` 与 `{名}-下.md`（先存盘再拆）。
- **排序**：文件树的视觉顺序就是唯一顺序来源——卷按卷号排，同目录内章按 `chapter-order.json` 排，
  没有手动顺序时按「第X章」里的章号排（中文数字、阿拉伯数字、罗马数字都认，所以新建的章会落在
  已有章的下方；不能交给拼音序，「第二章」会被排到「第一章」前面），最后才按文件名。拖拽只改
  侧车文件，不动正文；唯一不动顺序的例外是右键书的「反转卷与章的顺序」，它只影响左侧显示。
- **松散章夹在卷之间**：书目录里、卷之外的章（松散章）不必只能待在所有卷的上面或下面——把章行拖到
  **卷行的上 / 下边缘**，它就插到这一卷的前 / 后：落在「第二卷」的上边缘，就是夹在第一卷与第二卷
  之间；卷行**中间**那条带仍然是「拖进这一卷里」（插入线是横线、拖进是虚线框，松手前一眼能看出）。
  行是紧挨着排的，没有真的缝隙可落，所以夹层的落点长在卷行边缘上；源章本来就在这一卷里时整行只做
  「移入」，免得在卷内拖章时蹭到上沿被甩出卷外。
  记法上 `chapter-order.json` 的每个键存的是该目录**直接子项**的顺序，书目录那份因此可以同时列卷
  目录名与松散章文件名（如 `["第一卷 风起", "第二章.md", "第二卷 惊蛰"]`）。一份表里登记过卷就是
  「夹层模式」：登记过的排在没登记的前面、并按表里的位置排；没有卷名的表（旧工作区）则照旧「目录
  在文件前」，排列一点没变。卷改名、删除时表里的卷名会跟着改或摘掉；新建卷会插回卷堆里（接在最后
  一个卷后面），不会掉到表尾那个松散章下面。反转显示时整层倒过来，松散章仍夹在同样两卷之间，只是
  方向跟着倒。

### 小说工作台

默认收起，面板间可切换，展开状态与上次停留的面板会记住。资料存在**作品目录**的 `.novel/` 下：

- **伏笔**：正文选区右键「标注为伏笔」，可打标签、合并到已有伏笔；按状态分组
  （待回收 / 已回收 / 已废弃），支持阶段推进、彻底回收、恢复与筛选。
- **时间线**：事件按时间或类型分组，可关联章节与设定并跳转。
- **设定**：词条支持别名与关系（目标 + 关系名），引用按 id 记录，改名不丢关联；
  「关系图谱」是列表式邻接表——按关联度排序列出出边 / 入边，并统计边数、孤立词条与悬空引用。
- **校对**：对着当前打开的这一章挑错——错别字与敏感词词典、中文语境里的半角与重复标点、
  中文标点旁多余空格、中英混排的空格与全角标点、叠字（「他他」）等。每条给出位置、原文与建议，
  可以逐条「替换」或「忽略」，也可以「忽略同类」和「全部替换」；忽略记录写进
  `<作品目录>/.novel/proof-ignore.json`，下次不再打扰。

> 曾经的**专注计时 / 写作任务 / 写作历程**，以及工作台里的**「章节工具」**（新建下一章 / 导入切分 /
> 章节状态与字数目标 / 合并章节）都已移除：它们属于「通用写作工具」或与「专门写小说」的定位关系不大，
> 留在这里只会让工作台变臃肿。拆章保留在编辑器右键菜单里。

### 字数统计

状态栏点击可在三种口径间循环：

- **中+词**（默认）：CJK 字符逐字计，连续的西文字母 / 数字记 1 词，标点不计；
- **字符**：所有非空白字符（含标点）；
- **段落**。

统计前会剔除 frontmatter、`<!-- nw:no -->` 与 `nw:no:start/end` 标记块、围栏代码块与行内代码。

### 导出

所有导出都在本地完成，不发网络请求。只保留两种格式：

| 格式 | 范围 | 说明 |
| --- | --- | --- |
| Word `.docx` | 当前文档 | 真实 OOXML 容器，内嵌可用本地图片 |
| EPUB `.epub` | 当前文档 / 整本书 | EPUB 3（含 EPUB 2 兼容的 `toc.ncx`），整本书时按卷分组 |
| 复制为 Markdown | 当前文档 | 写入剪贴板 |

HTML 与「系统打印 / PDF」两条导出链路已移除（它们各自带着一整套纸面样式与打印分支，
而小说成稿走 DOCX / EPUB 就够）。渲染层内部仍会产出一份自包含 HTML，作为 DOCX / EPUB 的中间层：

- **图片**：工作区内的本地图片读成 data URL 内嵌，DOCX / EPUB 都能带上；文档里的远程图片只留
  「未下载」占位块，导出过程不发起任何网络请求。本地图片读不到时不会静默丢图——
  报告里列失败项，产物里也留下可见的错误占位。
- **DOCX**：格式降级会汇总成导出报告；Word 侧不生成公式对象（正文已不产出公式）。
- **EPUB**：`mimetype` 第一且不压缩、`META-INF/container.xml`、`content.opf`、`nav.xhtml`、`toc.ncx`、
  分卷页（卷标题取目录名的可读部分）、图片按内容 hash 去重。整本书导出时逐章取正文，
  **读不到某章就中止**，不生成空章。
- **导出报告**：DOCX / EPUB 出现降级或被拒绝的内容时弹出报告，涵盖源码回退、远程图片、
  图片读取失败 / 不支持 / 被丢弃、不安全链接、内部链接、不支持的标签等类别。

### 图片

- `Ctrl+Shift+I` 选择本地图片，复制进工作区 `assets/` 目录并插入相对路径（按当前文档层级自动补 `../`）。
- 目标重名会自动改名（`a-1.png`、`a-2.png`…），不覆盖旧文件。
- 全程本地处理，不联网。

## 工作区与数据

工作区是你自己选择的目录，与本项目源码目录不是同一个概念。一个工作区的典型结构：

```
我的小说/                      工作区根
├── 我的书/                    书 = 顶层目录
│   ├── outline/               纲要都在书文件夹里（不进文件树，只在「大纲」标签里导航）
│   │   ├── 总纲.md            书级总纲（新建书时自动建，名字固定）
│   │   ├── 第一卷 风起.md      卷纲（新建卷时自动建）
│   │   └── 第一章.md          章节纲要（右键章节按需建）
│   ├── 第一卷 风起/            卷 = 目录
│   │   ├── 第一章.md          章 = .md 文件（元数据在 frontmatter）
│   │   └── assets/            插入的图片
│   └── 第二章.md              不设卷时章直接放在书目录下
└── .novel/                    工作区级侧车（不显示在文件树里）
```

一个工作区里可以放多本书——每本书一个顶层目录，各自带一份 `outline/`。
左侧「大纲」标签把整个工作区的纲要按书分组列出来，不跟着当前打开的章走。

- **正文**：`.md` 文件，可以带 YAML frontmatter（`title` / `status` / `summary` / `words` / `goal`）。
  没有任何字段会被自动写回 frontmatter。
- **作品资料**：`<作品目录>/.novel/<name>.json`
  - `plot.json`（伏笔）、`timeline.json`（时间线）、`lore.json`（设定）
- **工作区级侧车**：`<工作区根>/.novel/`
  - `volumes.json`（卷注册表）、`chapter-order.json`（各目录内章的手动顺序；
    书目录那份也记卷目录名，松散章才能夹在两卷之间）、
    `order-flip.json`（哪些书在左侧反转显示，纯显示开关）
- `.novel/` 目录与点文件不会出现在文件树里。

复制或备份整个作品目录即可保留正文及配套资料。**建议为小说单独创建工作区**，例如 `~/Documents/小说`，
不要把 `/home/error02/Projects/MyNovel` 源码目录当成工作区。

写盘采用「同目录临时文件独占创建 + fsync + 原子替换」，失败会清理临时文件，尽量不留半截文件。

## 已知问题与已知限制

完整的作者视角清单在应用内「帮助 → 关于 MyNovel」。摘要：

**明确未实现**：正文的标题层级与表格、公式、脚注、图表、代码高亮、任务框等通用编辑器功能
（正文不提供插入命令，标题语法仍能渲染）；导入 txt/md 分章、勾选多章合并、章节状态与字数目标
（曾由工作台「章节工具」提供，已随该面板移除；拆章保留在编辑器右键菜单）；
多文件批量查找替换与正则替换预览（单文件查找替换、工作区搜索都有）；
LaTeX 文档导出、HTML / PDF / 打印导出、图床 / 云同步 / 分享 / 发布等一切在线能力、
主题切换（目前只有一套粉白亮色）。
EPUB 的封面与作者字段代码里已实现，但界面还没有填入口；整本批量导出目前只有 EPUB，DOCX 只导出当前文档。
「校对」面板做的是错别字词典与标点 / 空格规则，不等于完整的拼写与语法检查。

**已知问题（按影响排序）**：

1. **关窗时的异步保存在部分情况下来不及写完**（`beforeunload` 不等待异步 IPC）。
   没有自动保存，也没接 Tauri 的关窗请求，离开前请 `Ctrl+S`。
2. **复杂嵌套 Markdown 尚未完整兼容**：不支持的结构会保留 Markdown 源码显示，不会硬渲染出错。
3. **性能**：工作区搜索每次重扫磁盘、无上限也不能取消；超长章节里移动光标仍要重排整篇的块装饰
   （每个块的渲染结果已按文档缓存，不再逐块重跑 Markdown 渲染）。
4. **DOCX / EPUB 未在真实 Word、WPS 或专业阅读器里人工验收**，结构由容器部件与 XML 解析校验保证。
5. **中文输入法**的自动化测试使用合成 composition 事件，不等同于真实 Rime 候选窗验收。

### 最近修掉的

下面这些曾经是真的问题，现在不是了——列出来是因为旧版本的打包可能还带着：

- 章节直接放在工作区根目录时，作品资料的路径会算错，写不进去；现在根目录章的工作目录被正确当作空串，
  资料落在 `<工作区根>/.novel/`。
- 导出没有拦「别覆盖手稿」；现在 DOCX / EPUB 走同一道
  `validateExportTarget`，写盘前拒绝写成 `.md` / `.markdown` / `.mdx` / `.txt`，也拒绝写到源文件本身。
- 读取路径只做 `safe_join`；现在 `read_file` / 侧车读取 / `rename_entry` 都会再解析一次真实路径
  （`ensure_realpath_inside`），指向工作区外的符号链接会被明确拒绝。工作区搜索本来就是
  `WalkDir::follow_links(false)` + `is_file()`，不会跟随符号链接。
- 拆章之前不落盘、之后不刷新编辑器；现在拆分前先保存，拆完重读前半段
  （新增 `reloadFromDisk`），不会再把旧正文写回去。（当时的「合并章节」已随「章节工具」移除。）
- 沉浸写作的打字机居中不跟随输入；现在把 `typewriterMode` 直接传给编辑器（原先挂的那个
  `editor:update` 事件从来没被派发过，已删除）。
- `Ctrl+Shift+F` 在已经停在搜索页时再按一次会把侧栏收起来；现在快捷键与菜单走
  `openSidebarTab`（只打开不折叠）。点击标签本身同样不折叠——反复点当前标签（含双击）
  一旦收起，后面那一击又会让它弹回来，观感像「点着点着侧栏自己闪」，所以现在只剩显式的
  「视图 → 左侧栏」与 `Ctrl+Shift+L` 能收起侧栏。
- 「段落」菜单给「段落上移 / 下移」标了 `Alt+↑` / `Alt+↓`，而这两个键实际是编辑器的「移动单行」；
  现在菜单不再标这个键位。
- 右侧分隔条拖拽时叠加累计位移，越拖越偏；现在与其他分隔条一样以拖拽起点为基准。
- 长文档里每移动一次光标，即时预览都会把每个块拿整篇正文重跑一遍 Markdown 渲染（块数 × 全文行数，
  因为链接定义的收集要扫全文），章节越长越卡；现在每个块的渲染结果按文档对象缓存，文档没改
  就只重排装饰、不重跑渲染。文件树拖拽排序也改为按帧合并落点计算（原先是每个 pointermove 都整树量一遍）。

**分发与验收边界**：DOCX / EPUB 用 Python `zipfile` 与 `xmllint` 从容器外部独立校验，
但没有在真实 Word / WPS / 专业 EPUB 阅读器里做过人工视觉验收；中文输入法的自动化测试
使用的是合成 composition 事件，不等同于真实 Rime 候选窗验收（清单见 `scripts/EXPORT-IME-ACCEPTANCE.md`）。

wemeet 的图标数值一致：`/usr/share/icons/hicolor/scalable/apps/wemeet.svg`

`RADIUS_RATIO=0.2 npm run icons`）；脚本每次都从满幅母版重新生成，不会叠加圆角。
