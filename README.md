# MyNovel

MyNovel 是一款**本地优先**的轻量小说写作桌面应用。正文就是普通的 Markdown 文件，作品资料是同一目录下的人类可读 JSON——不依赖云端账户、不需要数据库、不联网。

技术栈：Electron + React 19 + TypeScript + CodeMirror 6（后端是 `electron/vault.cjs`）。当前版本 **v0.2.1**，分发形态是 Arch Linux 上的单文件 AppImage。

> **2026-10 换掉了 WebKitGTK**：原来跑在 Tauri 2 + WebKitGTK 上，那套在这台机器只给 31fps；换成 Electron（Chromium）后实测 **180fps**。原因与测量过程见下面「渲染帧率」一节。前端一行未改，只重写了后端。

## 打开软件

已经构建过的话，直接跑打好的 AppImage——不需要先装 npm 依赖，也不用起开发服务器：

```bash
cd <项目目录>
./release/MyNovel_<版本>_amd64.AppImage
```

从别处复制过来后若提示权限不足，先 `chmod +x` 那个文件。仓库里还没有构建产物的话，按下面「开发与重新打包」跑一次 `npm run app:build`。

打开窗口后点击 **选择工作区目录**，选一个存放小说的文件夹——空的可以在应用里建章，已有 Markdown 的目录也能直接读。之后用顶部的工作区名称换目录。

> **建议**：先在工作区根目录右键「新建书」，再进书里建卷和章。**纲要跟着书文件夹走**，只有属于某本书的章才有总纲 / 卷纲 / 章节纲要。章也可以直接放在工作区根目录（不建书、不设卷），照样能写能导出，只是这类章没有纲要。

`npm run dev` 起的浏览器预览拿不到原生文件系统，选不了工作区；要调桌面版用 `npm run app`（它同时起 Vite 和 Electron）。

## 界面一览

版式参照 Typora，配色是一套暖白柔粉的亮色主题（CSS 变量集中在 `src/styles.css` 的 `:root`）。

- **顶部菜单栏** —— 文件 / 编辑 / 段落 / 格式 / 视图 / 主题 / 帮助，快捷键提示右对齐；悬停即切换菜单，点外部或 `Esc` 关闭。
- **左侧栏**（默认展开，宽 272，可拖 200–560）—— 「文件 / 大纲」两个标签，最右侧的放大镜按钮开工作区搜索。点标签只切换不折叠，收起请用「视图 → 左侧栏」或 `Ctrl+Shift+L`。
- **正文区** —— 居中约 752px 栏宽（与 Typora 的 `#write` 一致），上方多标签页，有未保存改动时标签栏出现「保存」按钮。
- **右侧小说工作台**（默认收起，宽 340，可拖 240–640）—— 伏笔 / 时间线 / 设定 / 校对四个面板，导航按「创作 / 校对」分组收进下拉菜单，展开状态与上次的面板会记住；`Ctrl+Shift+B` 或右缘竖条把手召回。
- **底部状态栏** —— 左边是工作区名与当前文件相对路径；右边是 `行 X 列 Y`、选区长度、本章字数（点一下换统计口径）、全书字数，以及 `● N 未保存` 或最近一条状态文本。
- **弹窗里的小人** —— 设置 / 关于 / 帮助等所有弹窗右下角那个「思考中」的角色，与挂件用的是**同一张图**，整块待在弹窗右侧之外、与边框留缝；窗口窄到放不下（<860px）时整块隐藏。
- **伴读立绘** —— 稿纸**左侧**的人物（素材已水平镜像，面朝正文），贴着左侧栏站；左空白不够时缩到编辑区左下角。因为它是编辑区的子元素，左侧栏收起 / 拖宽时它跟着一起动，不需要额外监听。在「关于 MyNovel」里点应用图标可以开关。
- **欧金金**（右下角的挂件人物）—— 默认待在右下角的可点击人物：点一下压扁并叫一声，**左键按住可以拖着走**。拖动范围限制在正文区内：上不过顶部菜单栏、下不过状态栏、左不压左侧栏（与伴读立绘同一条线），松手吸附贴边，落点记在 `localStorage`（菜单里可「回到角落」）。右上角的菜单按钮跟着挂件等比缩放（18–32px），所以调到最小档也不会盖住人物；按钮可隐藏，改右键人物唤出。菜单里能拖「大小」滑块调尺寸、调音量、关音效、试听。**点一下人物会冒气泡**：大字是「今日已写」、小字是「平均速度」，5 秒自动收起。气泡的动效照参考项目复刻了两处：进场是**分段弹出**（尾巴先冒 → 本体带一点过冲地鼓出来 → 文字最后浮现，不是一次淡入），并且气泡和人物**同处一个被压扁的外壳里**，所以按住人物时它跟着一起抖；配色整套换成主题的粉白玫红。**已经显示着的时候再点人物不会重建气泡**（重建会把进场动画连文字一起重播，看着像被重置），只更新数字；**点气泡本身**会把正文交叉淡化换成彩蛋「欧金金…」（那行字在气泡里水平垂直都居中），再点切回来。开关在「视图 → 挂件 → 欧金金」。

## 功能清单

### 工作区与文件树

- 选目录打开工作区，自动记住上次那个；刷新会重扫磁盘。
- 新建章节 / 文件 / 文件夹 / 书 / 卷 / 章节纲要，建完就地行内改名（`Enter` 提交、`Esc` 取消、失焦也提交，名字非法则回退）。
- 删除前弹确认框，列出会一并走掉的纲要，以及「N 个未保存修改会丢失」。
- 拖拽排序：落到章行上插到它前 / 后，落到目录行上整体移入，落到**卷行的上 / 下边缘**插到那一卷的前 / 后（松散章夹进两卷之间走这里），也能拖回根目录；跨目录移动重名会自动加序号。
- 卷行显示「N 章」，章行显示字数；当前文件高亮。
- 右键**书文件夹**可「反转卷与章的顺序」：把这本书的卷与章在左侧倒过来列。这是**纯显示**开关，顺序侧车、阅读顺序与 EPUB 导出都不受影响，所以反着显示时拖拽方向会自动换算。

### 大纲页

- 左侧「大纲」标签是整个工作区的纲要导航树，按 书 → 卷 → 章 排列，不跟着当前打开的章走。
- 书行就是这本书的总纲（玫红，固定 `总纲.md`），卷行是卷纲（青蓝），章行是该章的章节纲要（缩进在所属卷下）。顺序取自文件树的同一份排序，卷号与手动章序两边永远一致。
- 点任意一行就在正文区打开它——和章节一样是个标签页，同一台编辑器、同一套即时预览与输入法处理，`Ctrl+S` 保存。
- 还没有的章节纲要显示成虚线「＋」，点一下按章名建出来；双击除总纲外的行可以改名；每本书的书行可以折叠。

### 编辑与即时预览

- **即时预览**：光标所在的块显示 Markdown 源码，其余块渲染成排版后的样子。预览与导出走同一份渲染器，做到「预览所见即导出所得」。渲染不了的结构保留完整源码并标记提示，不会静默丢弃内容。
- **支持语法**：粗体、斜体、下划线、删除线、行内代码、行内 / 引用式 / 自动链接、图片、引用块、无序与有序列表、分割线、围栏代码块、缩进代码块、YAML frontmatter（折叠卡片）、行内 HTML；标题（ATX / Setext）照常渲染，`总纲.md` 就靠 `# 书名` / `## 第N章` 分层。
- **预览是只读的**：点渲染块只把光标移到该块起点，绝不把渲染结果写回正文。
- **输入法**：组合期间推迟源码模式重配、打字机滚动与外部正文同步，组合结束再结算；外部内容与本地输入冲突时保留本地文字，只合并互不重叠的改动。
- **正文右键菜单**：标注伏笔、复制、加粗 / 斜体 / 删除线、超链接、插入图片、在此拆分章节。
- **链接**：`Ctrl+点击` 打开外部链接、锚点或工作区内其它文件；目标文件不存在时询问是否创建。

### 视图与排版

- **三种视图模式**：源码 `Ctrl+/`、专注 `F8`（提亮当前段落、其余变淡）、打字机 `F9`（光标行垂直居中）。切换模式不改动也不丢失正文。
- **沉浸写作**：独立全屏写作视图，顶栏 `A−` / `A+` / `A0` 直接调字号，`Esc` 保存并退出，双击正文切换居中。
- **浮动格式工具栏**：选中文字后在选区上方浮出加粗 / 斜体 / 删除线 / 超链接 / 插入图片，可在「视图 → 浮动工具栏」关闭。
- **段落操作**（「段落」菜单）：分割线、段落上移 / 下移 / 复制 / 删除。

### 查找与导航

- **快速打开** `Ctrl+P`：子序列模糊匹配，↑↓ 选择、`Enter` 打开。
- **文档内查找 / 替换** `Ctrl+F` / `Ctrl+H`。
- **工作区搜索** `Ctrl+Shift+F`：跨文件全文搜索，支持正则与区分大小写，结果按 `文件:行号` 列出。

### 卷、章与纲要

- **卷 = 目录**：目录名匹配「第X卷 / 卷X / Volume N」即识别为卷，也可以由卷注册表登记（「新建卷」创建的目录走注册表）。整本书可以不设卷，章直接放在书目录下，此时都是「松散章」，EPUB 目录保持扁平。
- **章 = `.md` 文件**：新建的章正文是**空白**的——章节名由文件名管理，正文里不生成 `# 标题`，免得改名后两处打架。
- **默认章名接着上一章排**：目录里阅读顺序最后一章叫「第三章」，新建的就叫「第四章」。中文数字、阿拉伯数字、罗马数字各排各的，`第一章 启程` 这种带标题的也算（新名只给章号）。只看前一章叫什么，不检查编号是否连号。空目录或前一章不是「第X章」格式（比如「楔子」）时用 `Untitled`；重名自动避开（`Untitled`、`Untitled 2`…）。
- **拆章**：编辑器右键「在此拆分章节」，从光标处拆成 `{名}-上.md` 与 `{名}-下.md`（先存盘再拆）。
- **纲要文件**一律放在**书文件夹**的 `outline/` 下，都是可改名可编辑的普通 `.md`：
  - `书/outline/总纲.md` —— 书级总纲（名字固定），新建书时自动建；
  - `书/outline/<卷目录名>.md` —— 卷纲，新建卷时自动建，卷改名时跟着改名；
  - `书/outline/<章文件名>.md` —— 章节纲要，右键章节「新建章节纲要」按需建。
- 书改名时整份 `outline/` 随目录一起搬；有章却没有总纲时自动补建。纲要不计入字数、不进 EPUB 章节列表。
- **删除会带上对应纲要**：删除确认框会把要一起走掉的纲要列出来，不留对不上任何章的孤儿。

### 排序

- 文件树的视觉顺序就是唯一顺序来源：卷按卷号排，同目录内章按 `chapter-order.json` 排；没有手动顺序时按「第X章」里的章号排（中文 / 阿拉伯 / 罗马数字都认），最后才按文件名。
- **松散章夹在卷之间**：把章行拖到卷行的上 / 下边缘，它就插到这一卷的前 / 后。`chapter-order.json` 的每个键存的是该目录**直接子项**的顺序，书目录那份因此可以同时列卷目录名与松散章文件名，例如 `["第一卷 风起", "第二章.md", "第二卷 惊蛰"]`。卷改名、删除时表里的卷名会跟着改或摘掉。
- 拖拽只改侧车文件、不动正文；唯一不影响顺序的例外是右键书的「反转卷与章的顺序」，它只改左侧显示。

### 小说工作台

默认收起，面板间可切换，展开状态与上次停留的面板会记住。资料存在**作品目录**的 `.novel/` 下：

- **伏笔**：正文选区右键「标注为伏笔」，可打标签、合并到已有伏笔；按状态分组（待回收 / 已回收 / 已废弃），支持阶段推进、彻底回收、恢复与筛选。
- **时间线**：事件按时间或类型分组，可关联章节与设定并跳转。
- **设定**：词条支持别名与关系（目标 + 关系名），引用按 id 记录，改名不丢关联；「关系图谱」按关联度列出出边 / 入边，并统计边数、孤立词条与悬空引用。
- **校对**：对着当前打开的这一章挑错——错别字与敏感词词典、中文语境里的半角与重复标点、中文标点旁多余空格、中英混排的空格与全角标点、叠字等。每条给出位置、原文与建议，可逐条「替换」或「忽略」，也能「忽略同类」「全部替换」；忽略记录写进 `<作品目录>/.novel/proof-ignore.json`，下次不再打扰。

### 字数统计

**默认口径是「字符」：每个非空白字符算 1** —— 汉字、英文、数字、标点都算进去，空格 / 换行 / 制表符不算。
左侧文件树的数字、状态栏的「全书」、挂件的「今日已写」、沉浸模式的字数都是这个口径，共用
`src/lib/wordcount.ts` 一处实现（别在别处另写一份：口径不一致的话，保存 / 刷新那一刻数字会跳）。

状态栏那一格点一下在三种口径间循环。**切换只影响「本章」这个数字**，全书与左侧树固定走默认口径：

- **字符**（默认）：所有非空白字符（含标点）；
- **中+词**：CJK 字符逐字计，连续的西文字母 / 数字记 1 词，标点不计；
- **段落**。

统计前会剔除 frontmatter、`<!-- nw:no -->` 与 `nw:no:start/end` 标记块、围栏代码块与行内代码。
**输入法组合中的拼音不算**：候选窗还开着时正文里是拼音字母，字数与统计一律等**落定**（上屏、提交落盘）之后
再算，免得按拼音涨一遍、上屏后又退不回来。落定那一刻哪怕没有新的正文变化，编辑器也会补报一次（`test-ime-count` 钉着这条）。

### 导出

导出全部在本地完成：

| 格式 | 范围 | 说明 |
| --- | --- | --- |
| Word `.docx` | 当前文档 | 真实 OOXML 容器，内嵌可用本地图片 |
| EPUB `.epub` | 当前文档 / 整本书 | EPUB 3（含 EPUB 2 兼容的 `toc.ncx`），整本书时按卷分组 |
| 复制为 Markdown | 当前文档 | 写入剪贴板 |

- **图片**：工作区内的本地图片读成 data URL 内嵌；文档里的远程图片只留「未下载」占位块。本地图片读不到时不会静默丢图——报告里列失败项，产物里留下可见的错误占位。
- **EPUB**：`mimetype` 第一且不压缩、`META-INF/container.xml`、`content.opf`、`nav.xhtml`、`toc.ncx`、分卷页（卷标题取目录名的可读部分）、图片按内容 hash 去重。整本书导出时逐章取正文，读不到某章就中止，不生成空章。
- **导出报告**：出现降级或被拒绝的内容时弹出报告，涵盖源码回退、远程图片、图片读取失败 / 不支持 / 被丢弃、不安全链接、内部链接、不支持的标签等类别。
- 导出目标会做校验：拒绝写成 `.md` / `.txt` 等源文件格式，也拒绝覆盖源文件本身。

### 图片

- `Ctrl+Shift+I` 选本地图片（可多选），复制进工作区 `assets/` 并按当前文档层级插入相对路径（自动补 `../`）。
- 目标重名自动改名（`a-1.png`、`a-2.png`…），不覆盖旧文件。

### 外观与设置

- **字体与排版**（`Ctrl+,`）：编辑器字体族（宋体 / 黑体 / 中圆体 / 等宽预设，或自定义字体名）、字号 12–34px、行距 1.3–2.8。即时生效，写在 `localStorage`，常规编辑器与沉浸写作共用同一套变量。
- **窗口级缩放** `Ctrl+Shift+=` / `Ctrl+Shift+-`，`F11` 全屏。
- 栏宽、左侧栏与工作台的开合状态、上次的工作区都会记住。

## 工作区与数据

工作区是你自己选的目录，和本项目源码目录不是一回事。一个工作区的典型结构：

```
我的小说/                      工作区根
├── 我的书/                    书 = 顶层目录
│   ├── outline/               纲要都在书文件夹里（不进文件树，只在「大纲」标签里导航）
│   │   ├── 总纲.md            书级总纲（新建书时自动建，名字固定）
│   │   ├── 第一卷 风起.md      卷纲（新建卷时自动建）
│   │   └── 第一章.md          章节纲要（右键章节按需建）
│   ├── 第一卷 风起/            卷 = 目录
│   │   ├── 第一章.md          章 = .md 文件
│   │   └── assets/            插入的图片
│   └── 第二章.md              不设卷时章直接放在书目录下
└── .novel/                    工作区级侧车（不显示在文件树里）
```

一个工作区里可以放多本书——每本一个顶层目录，各自带一份 `outline/`。

- **正文**：`.md` 文件，可以带 YAML frontmatter（`title` / `status` / `summary` / `words` / `goal`）。没有任何字段会被自动写回 frontmatter。
- **作品资料**（顶层书目录下的 `.novel/`；章在根时是工作区根）：
  - `plot.json` —— `{"items":[Foreshadow]}`，每条含 `id` / `description` / `tags` / `status`（`open` / `done` / `abandoned`）/ `sourcePath` / `sourceLine` / `sourceText` / `createdAt` / `stages` / `resolvedChapters`
  - `timeline.json` —— `{"items":[{id,time,title,type,chapters[],lore[],note}]}`
  - `lore.json` —— `{"items":[{id,name,type,aliases[],content,sourcePath,relations[{target,label}]}]}`
  - `proof-ignore.json` —— `{"ignores":["kind|ruleId|text"]}`（不含行号）
- **工作区级侧车**（工作区根 `.novel/`）：
  - `volumes.json` —— `{"volumes":["第一卷 风起", …]}`，卷注册表
  - `chapter-order.json` —— `{"<目录相对路径>":["a.md","b.md"]}`，各目录内直接子项的手动顺序
  - `order-flip.json` —— `{"books":["我的书"]}`，哪些书在左侧反转显示（纯显示开关）
- 全部 JSON 都是 `JSON.stringify(…, null, 2)`，可以直接看、直接改。
- 扫描时跳过任何以 `.` 开头的文件 / 目录，以及 `node_modules` 和名为 `obsidian` 的目录；`.novel/` 与点文件不出现在文件树里。
- 写盘用「同目录临时文件独占创建 + `fsync` + 原子替换」，失败会清理，尽量不留半截文件。
- 应用设置不在工作区里，存在 WebView 的 `localStorage`：`mynovel:typography`、`mynovel:workbench-open`、`mynovel:work-tab`、`mynovel:companion`、`mynovel:last-root`、`novel.immersive`。

复制或备份整个作品目录即可保留正文及配套资料。**建议为小说单独创建工作区**（例如 `~/Documents/小说`），不要把本项目的源码目录当成工作区。

### Windows

Windows 上只要 Node.js（打 Electron 包不需要 Rust / GTK3 / WebKit2GTK，那几个只有
`scripts/test-*-webkit.mjs` 那批旧 WebKit 用例还要）：

产物：

| 文件 | 说明 |
| --- | --- |
| `MyNovel_<版本>_x64_Setup.exe` | 用户级安装（`%LOCALAPPDATA%\Programs\MyNovel`），不弹 UAC，带开始菜单 / 桌面快捷方式；设置存在 `%APPDATA%\com.local.mynovel`，卸载不删 |
| `MyNovel_<版本>_x64_Portable.exe` | 单文件免安装版 |

首次打包有一个 Windows 特有的坑：electron-builder 要解压 `winCodeSign-2.6.0.7z`，那个包里带着
macOS 的符号链接，普通用户解压会 `EPERM: Cannot create symbolic link`。两种解法，任选其一：

1. 打开「设置 → 系统 → 开发者选项 → 开发人员模式」（管理员操作一次）。这同时也让
   `npm run test:vault` 能跑——那批用例靠符号链接验证「工作区外逃」的防护；
2. 或者不升权限，手工把 Windows 用得着的那部分铺进缓存（build 失败一次之后 .7z 才会出现在缓存里）：

   ```powershell
   $cache = "$env:LOCALAPPDATA\electron-builder\Cache\winCodeSign"
   $arc = Get-ChildItem $cache -Filter *.7z | Sort-Object LastWriteTime -Descending | Select-Object -First 1
   & node_modules\7zip-bin\win\x64\7za.exe x $arc.FullName "-o$cache\winCodeSign-2.6.0" "-x!darwin" -y
   ```

安装包目前**没有签名**，首次运行 Windows 会弹 SmartScreen「未知发布者」，点「更多信息 → 仍要运行」即可。
`scripts/release.sh` 是 Linux 专用的（bash + gh + AppImage），Windows 侧目前只到「构建产物」这一步。

### 气泡的两个动效（都照参考项目）

1. **分段弹出**：参考项目的气泡由三层形状组成（两个小尾巴泡 + 主体），打开时按 `0s / .13s / .26s` 依次从
   `scale(.7)` 弹起，文字再晚一步（`.36s`）淡入。这里用同一条思路排三段——尾巴 `0s` → 本体 `.07s`（带 `1.06` 的过冲回弹）
   → 文字 `.2s`。实测（真 Electron 逐帧采样）：不进场的瞬移，而是缩放走过 **35 档**、透明度 20 档，最大缩放 **1.060**，
   文字起始确实隐藏。
2. **跟着人物一起抖**：参考项目把气泡和鲸鱼本体放在**同一个被压扁的 `div`** 里（`pressDown` 时对该 div 施加
   `scaleY(.88) scaleX(1.05)`），气泡自然跟着抖。这里同样把气泡放进 `.pw-figure`，压扁作用在这一层。
   实测按住时气泡位移 **35px**。手感也照它改成了**按下就压、松手回弹**（原来是在松手后才压一下）。

## 写作统计（气泡里那两个数）

- **今日已写** = 今天字数**净增的累加**：每次全书总字数比上次多，就把多出来的累加；变少（删了东西）不动它。
  不用「当前总数 − 今天开始时的总数」，那样删一段再写回来就不算了，而且换工作区会把基准冲掉、一下算出个天文数字。
  换工作区时只重建基准、**不**累加（识别依据是工作区路径）。
- **平均速度** = 今日已写 ÷ 活跃时长。活跃时长按「两次输入间隔不超过 90 秒就累加」来记，开着窗口去吃饭不会被摊平；
  活跃不足 **30 秒**不给数，显示 `—（再写 N 秒）`：分母只有几秒时会算出几万字/时这种荒唐数，得拦一下；
  而写成「再写 N 秒」是**别让它只留一条光秃秃的横线** —— 刚重置完或刚换到这一版时基准归零，
  那条横线看着就像功能坏了（实测被这么问过）。

- **数字是实时的**：气泡开着的时候你继续打字，两个数会跟着涨。数字不存 state —— 渲染时现读 `getToday()`，
  气泡开着时每 200ms 重渲染一次（气泡最多活 5 秒，约 25 次 setState；关着时一次都不跑，按键路径上一个字节的开销都没有）。
  统计的口子叫 `store.feedBookWords`：挂在章节字数上（正文改动后 100ms 节流一收就喂一次），界面怎么翻都不动它 ——
  **别挪到界面上去喂**，切章节 / 切统计口径抖出来的差值会被当成「今天写的字」（踩过两次）。
- **菜单里有「重置今日已写」**（「写作统计」分组）：把今天的字数与活跃时长一起清零并立即落盘——只清字数不清时长的话，
  速度会被之前那段时长摊平得没法看。点完顺手把气泡叫出来显示 0，不然菜单一关看不出成没成。

数据存 `localStorage` 的 `mynovel:writing-stats`，按天分桶（为以后的连续天数 / 热力图留了路）。
两个钩子都不重：`store.setContent` 每次按键只调一次 `noteEdit()`（几次算术 + 节流 2 秒才落盘，按键路径上不碰
localStorage），全书字数则由 `StatusBar` 喂过去——那里本来就算着，不必再扫一遍文稿。

存档里带 `version`（当前 **2**）：**字数口径变了就要 +1**，对不上的旧存档整份作废、今日已写归零一次 ——
否则升级那一刻「旧口径的基准 vs 新口径的总数」的差（标点那部分，实测一两千字）会被记成今天写的。
口径本身只有 `src/lib/wordcount.ts` 一份，左侧树 / 全书 / 统计 / 本章都吃它（别在 store 里另写一套）。

## 渲染帧率（为什么从 Tauri 换到了 Electron）

这台开发机：NVIDIA RTX 4060 + niri/Wayland + **180Hz** 屏。原来跑 Tauri 2 + WebKitGTK 时，**整个应用**只有 **31fps**——这就是「人物模型卡顿」的根因，而且一直如此（与挂件无关）。

### 换之前：WebKitGTK 只有 31fps

- 在**真实应用**里量 rAF：均值 31.96ms、p50 32、p95 33、max 33 —— 不是偶发掉帧，是稳定的 30fps 上限；
- 同一进程里 GTK 自己的帧时钟是 **60Hz**（16.46ms，很稳），WebKit 只回调了它的一半；
- 逐个排查**全部无效**：纯软件渲染（`LIBGL_ALWAYS_SOFTWARE=1` / `llvmpipe`）、`WEBKIT_DISABLE_DMABUF_RENDERER`、`WEBKIT_DISABLE_COMPOSITING_MODE`、`WEBKIT_USE_SKIA_FOR_COMPOSITION`、`WEBKIT_DMABUF_RENDERER_FORCE_SHM`、`WEBKIT_FORCE_VBLANK_TIMER`、`WEBKIT_DISPLAY_REFRESH_THROTTLE_FPS`、`GDK_BACKEND=x11`、`__GL_SYNC_TO_VBLANK=0`；连 `hardware-acceleration-policy` 的三档都试了；
- 连**纯色方块**也一样 31.1fps → 与页面内容无关，是引擎的帧调度；
- `visibilityState === "visible"`、`hasFocus() === true` → 不是「窗口不可见」的节流；
- 一个可上报的线索：**GDK 读到的刷新率是 `180003 Hz`**（真值 180，差 1000 倍，niri 很可能按 mHz 上报）。

### 换之后：Chromium 179.9fps

同一台机器、同一个 niri、同一块屏，用同一套 rAF 探针量：

| 引擎 | 静止 | CSS 动画中 |
|---|---|---|
| WebKitGTK（原 Tauri） | 31.1 Hz | 31.1 Hz |
| Gecko（Firefox） | 168.5 Hz | 176.5 Hz |
| **Chromium（Electron 44）** | **169.4 Hz** | **180.0 Hz** |

所以问题在 WebKitGTK 而不在机器：Gecko 和 Chromium 都能吃满 180Hz。**打包后的 AppImage 实测 179.9fps**（编辑器已打开、挂件在场）。

### 顺带救回来的东西：菜单之间的过渡

菜单面板在菜单之间「滑过去」的过渡，当年是被**故意删掉**的（`shell.css` 里留着原因：
光标扫过菜单栏时动画每隔几毫秒被下一次位置变更打断，在 WebKit 下明显顿挫）。换引擎后
把它加回来了——只动 `transform / width / height`（合成器自己插值），打开时淡入一次，
**没有**恢复当年那套 `requestAnimationFrame` 双帧状态机（Chromium 会从当前实际位置平滑
改道，光标的连续悬停天然就是连续的）。

实测（在真实 Electron 进程里逐帧采样：在菜单之间来回悬停 6 次）：

| | WebKitGTK（旧夹具） | Chromium（现在） |
|---|---|---|
| 过渡中面板经过的位置数 | 1（瞬移） | **39**（真的在插值） |
| 帧间隔 | 32ms ≈ 31fps | **5.55ms ≈ 180fps** |
| 超过 20ms 的帧 | — | **0** |

### 迁移代价

- 前端 **15,808 行**一行未改 —— 因为后端调用本来就都收在 `src/api.ts`，换引擎只改了那一个文件，外加 `App.tsx` 里两行（全屏、打开外链）；
- 后端 **1,525 行 Rust → `electron/vault.cjs`**（约 690 行）；Rust 侧的安全不变量连同它的 `cargo test` 一起搬成了 `scripts/test-vault.mjs`；
- 体积：AppImage **108MB → 125.7MB**。注意原来的 AppImage 里光 `libwebkit2gtk` + `libjavascriptcoregtk` 就占 135MB —— 也就是说这个应用本来就在分发一整套浏览器引擎，只是那套慢。
